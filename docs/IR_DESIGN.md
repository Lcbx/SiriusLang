# Sirius compiler IR — target architecture

> Paths and commands in this document are relative to the repository root.

**Status:** Sirius uses typed/specialized HIR → ownership-aware CFG MIR → C11 as
its default self-hosted compilation pipeline. `src/modular_cli.sirius` is the default
entry point, and `bootstrap/compiler.c` is generated by its native module graph. The original AST-to-C emitter has been retired following MIR self-hosting
validation. The default suite exercises 96 compiled positive fixtures,
including indexed augmented assignments; some interpreter
operations remain future work. MIR ownership and C storage use interned type
descriptors; reserved primitive TypeIds remain part of the current ABI. The archived Python
bootstrap is not in use. The AST remains an indexed arena. For status and
remaining ownership work, see [ROADMAP.md](history/ROADMAP_20261025.md) and
[INTERPRETER.md](INTERPRETER.md).

The intended pipeline is **tokens → syntax AST → typed/specialized HIR → ownership-aware CFG MIR → (interpreter | C11)**. MIR forward ownership states now use packed 63-bit words; older dense-array profiling notes describe historical measurements. The incremental bridge already stores `HirNode(source, operation, type_id, field_index)`, where `source` refers back to the syntax AST. Literal, name, field, unary/binary and call-signature resolution is C-independent; HIR now validates builtin and user-function calls, string methods, array/dictionary methods, and record field composition (spread, delete, replace) and constructor publication using canonical descriptors. HIR analysis constructs these nodes before MIR lowering and C emission. HIR owns specialization cache keys and lifecycle. A pre-emission HIR declaration pass now indexes module functions and verifies declaration names, parameter syntax/uniqueness and deprecated `def` constructors before C output begins. The body pass now uses that declaration index to resolve concrete calls (including forward references), check annotated arguments, infer nonrecursive generic return types through nested calls, and type constructor-produced records. Unresolved/recursive cases remain deferred. Specialization keying and in-progress tracking now belong to HIR (`HirSpecializationRegistry` keyed by function-body AST identity plus canonical argument TypeIds); the HIR-to-MIR builder initiates specializations and owns the resulting typed bodies; the body pass is not yet a complete specialized HIR. The current type table is a semantic identity registry (dense `TypeId` indices, descriptor tags and child IDs); runtime size/alignment/field offsets are not yet stored in the semantic descriptors. The C backend derives C representation, field payload selection and managed retain/drop behavior from descriptor tags and field types; the verifier ensures reserved primitive TypeIds cannot be rebound. Exported module/library type signatures likewise inspect descriptor tags, not numeric ID ranges, and recurse through validated canonical child IDs. The shared canonical descriptor check rejects malformed or cyclic descriptors during construction and MIR/generic declaration deserialization; invalid construction preserves the type table and yields TypeId 0 (`TYPE_TAG_INVALID`). MIR verification additionally checks operation-specific constraints such as hashable dictionary keys. HIR composite checks and MIR lowering now query `Types.type_tag` / `Types.type_has_tag`, which return an invalid tag for out-of-range IDs rather than indexing blindly. Primitive TypeIds 0–5 remain reserved and scalar opcode selection still compares these stable constants; the overall migration remains open. The earlier illustrative Python target-IR experiment has been removed. The current Sirius AST is an indexed arena (`Array[Node]` plus child edges), not the original Python syntax AST.

### Historical source-to-MIR migration

The HIR worklist now resolves named `rec` return/parameter annotations by canonical published fields, including nested `Array`/`Optional`/`Dict` annotations. Constructor calls are lowered directly into `MIR_RECORD_NEW` in published-field evaluation order, with canonical physical ordering. Top-level integer constants are resolved independently of the C emitter. The lowering additionally supports empty typed arrays, array append (`MIR_ARRAY_APPEND`, consuming owner), array/range `for`, loop control, expression statements, and CLI/file/string conversion intrinsics. Native MIR-C initializes the arguments runtime and converts CLI strings into MIR-owned arrays; MIR interpreter file reads are deferred. MIR-only native self-hosting reaches a fixed point and all 91 executable fixtures pass. Two historical negative fixtures are accepted by MIR as valid programs (floating-point arrays and `elif` optional fallback).

### Concrete specialization worklist (implemented subset)

`src/hir_specialize.sirius` types each reachable concrete function once, using a HIR-owned queue keyed by `(declaration body ID, canonical argument TypeIds)`. A request is registered before callee analysis; calls to `IN_PROGRESS` entries resolve to the same specialization ID (including mutual recursion). Every `HirSpecializedFunction` records its typed nodes, resolved call targets and return type. The body array index **is** the stable specialization ID (there is no duplicate per-body ID field). HIR specialization analysis does not depend on either backend. Nonrecursive unannotated generic return types are inferred by analyzing the concrete callee body. Recursive unannotated returns remain rejected; richer inference and effects analysis remain future work.

`src/mir_program.sirius` consumes that worklist and lowers its supported scalar/string/record subset. The `MirProgram.functions` index is the specialization ID; `MIR_CALL` uses the same index. The HIR registry, typed bodies and type table are local to the builder; the public `MirProgramBuild` contains the MIR program, entry index, error and named import/export tables. Resolved `HirSpecializedCall` targets pass directly to MIR lowering, without a second call-target record or conversion array. The canonical type table is attached to `MirProgram`, rather than retained twice at the HIR/MIR boundary. MIR native C supports `i64`, `bool`, `f64` (including arithmetic, comparisons and `sqrt`), owned strings, structural records, rank-1 arrays, dictionaries, optionals, record spread/delete, and tail `recur`. Nested record and checked-array projections support assignment and numeric/string compound updates through path reconstruction. The MIR interpreter supports floating-point operations and file I/O.  The default `src/mir_emit_c.sirius` consumes verified linked MIR, including its worklist-owned specialization indices, and uses no emitter-local specialization cache.

## Syntax AST (implemented in the Sirius compiler)

Both parsers preserve indentation-sensitive blocks, declarations (`let`, `var`), constructors (`pub`), record operations, loops, `match`, indexing modes, and source positions. The Sirius parser uses source byte spans and flat node/edge arrays; future HIR must retain those spans for diagnostics. Expression precedence and short-circuit behavior are semantic obligations, not properties of C emission.

The executable HIR-to-MIR bridge maintains a sparse index from AST node IDs to
HIR annotation chains. This avoids repeatedly searching the annotation list and
preserves distinct operations on a node. Canonical `TypeTable` descriptors are
cached by stable structural keys while keeping insertion-order numeric `TypeId`s.
The MIR-C emitter now accumulates generated fragments before joining sections,
function bodies and the full translation unit. Normal source compilation uses
`mir_emit_c_verified` after CFG ownership, lifetime and balance validation.
This removes redundant register-read initialization checks and uses `NULL` as
an empty ownership state for managed C pointers instead of per-register flags.
Scalar registers need no runtime initialized-state tracking. Guarded arithmetic,
index and optional operations rely on their explicit MIR CFG panic edges.
For native linked MIR libraries, `mir_emit_c_reachable` traverses `MIR_CALL`
and `MIR_CALL_MOVE` from the selected entry, removes unrelated exported
functions, remaps concrete call indices and invokes the defensive C emitter.
This produces a self-contained C executable without changing the linked `.smirl`
artifact. Single-file compiler mode retains its verified MIR-C fast path.
The separate `mir_emit_c` entry point retains defensive initialization checks
for arbitrary hand-constructed MIR, including tests of invalid register reads.
The verified emitter omits its function-wide exit-release sweep: the preceding
CFG cleanup pass already emits the required explicit releases, and balance
validation proves other managed registers are dead on every return. The
defensive entry point retains the release sweep. Both paths retain reference
counting and path-sensitive cleanup semantics.
These are compiler-internal representation changes, not changes to source-language
value semantics.

## Typed HIR

* Each expression has an interned `TypeId`, source `Span`, and resolved symbol/function identity.
* Canonical record types intern by lexicographically sorted field names/types, not constructor names. Different shapes use distinct `TypeId`s. The emitted MIR C representation uses sorted field indices in `S_MirField` slots; byte offsets and alignment follow the target C ABI, not a portable packed-record layout.
* Generic calls are specialized by `(definition SymbolId, concrete argument TypeIds)`; resolved function calls refer to the specialization. The return type and effect signature are attached to the specialization. Avoid recursively instantiating the same in-progress specialization.
* A constructor becomes an ordinary function producing an immutable record. Validate unconditional field publication, freeze published bindings, and statically resolve field layouts.
* Extension method calls become ordinary calls with the receiver inserted as the first argument.
* Operator overloads become statically resolved function calls (or known primitive operations).
* Indexing is explicitly `PROVEN`, `OPTIONAL`, or `PANIC` at the HIR level. The type of an `OPTIONAL` index is `Optional[element_type]`.
* Structural-field lookups are replaced with integer field indices. Dynamic `Any` is not part of the first bootstrap.
* Function values have a typed signature and effect guarantees. Noncapturing lambdas become named, generated functions.
* Purity checking uses a transitive call graph; panics are permitted in otherwise pure functions, whereas I/O and impure FFI are effects.

## Lowered MIR (CFG)

`src/mir.sirius` currently defines typed `MirProgram`, `MirFunction`, `MirBlock`, `MirInstruction` and `MirTerminator` records for scalar, string, record, array, dictionary and optional values. `mir_verify` validates instruction operands, result types, signatures and CFG targets; `src/mir_interpreter.sirius` executes them using typed register slots. `MIR_CALL` uses explicit argument-register indices, with limits for total steps and call depth. They now accept **checked scalar/string/record HIR lowering output**, including calls linked by `src/mir_program.sirius` from the HIR worklist, and are tested against `mir_execute`; the default MIR C emitter consumes the same `MirProgram`, with no separate AST-to-C fallback. The implemented managed operations include string construction/concatenation/length, record construction (`MIR_RECORD_NEW`) field extraction (`MIR_RECORD_GET`), and consuming CoW field updates (`MIR_RECORD_SET`), plus `MIR_COPY`, `MIR_RETAIN`, `MIR_MOVE` and `MIR_RELEASE`. Every initialized string/record register owns a reference. Record construction and field reads retain nested managed values; C copies share immutable reference-counted records and releases recursively drop nested strings/records. Ordinary calls retain arguments and returns transfer ownership. After lifetime insertion, managed arguments released immediately after a call can be transferred instead: `MIR_CALL_MOVE` consumes one or more distinct managed argument registers that each occur exactly once in the call. Its `first` field names the first moved register and `second` holds a positional bitmask of additional moved arguments (positions 0–61); calls with more arguments simply retain any unrepresentable ones. The verifier and forward/backward ownership analyses invalidate all transferred registers; interpreter and C emission transfer the same ownership credits. Duplicated registers and values used later are never transferred, while other distinct eligible arguments can still move. The interpreter maintains a record heap with equivalent logical reference credits. Managed collections, direct record updates, and CFG lifetime/exit-cleanup passes now have experimental coverage; complete ownership proofs and borrows remain future work. See [INTERPRETER.md](INTERPRETER.md) and [OWNERSHIP.md](OWNERSHIP.md) for
the current register, nested-heap-edge, and calling-frame credit contracts,
including precise limitations of the static proof.

A function is `FunctionMIR(locals, arguments, blocks, entry)`.
Each basic block holds ordered instructions and one terminator (`Jump`, `Branch`, `Switch`, `ReturnTerm`, or `PanicTerm`).

* Expressions become typed temporaries, making evaluation order explicit before the C backend sees them.
* `if`, `elif`, `and`, `or`, `while`, `for`, and `Optional` fallback become CFG branches. In particular, **`and`/`or` are not eager arithmetic instructions**.
* `for i in a..b` lowers to integer bounds and a loop (confirmed half-open).
* `recur f(a, b)` evaluates **all** new arguments first and then jumps to the function's entry block. Direct self-tail recurrence never creates another C call frame.
* `let Result = Success | Failure` defines a compile-time type alias for a union of **labeled** constructor alternatives. `Success` and `Failure` remain purely structural record constructors; the label is carried only by the union alternative. Union `|` in this declaration is a type operation, distinct from bitwise integer `|`.
* Constructor patterns such as `Success(value)` resolve both the constructor label and its structural payload shape. HIR checks label-based exhaustiveness and records the selected canonical tag for MIR lowering, even if two payload shapes are identical. `enum Color` is shorthand for empty `rec` declarations and a labeled union.
* Canonical union descriptors sort unique `(label, record TypeId)` pairs by label and preserve them through module type translation and MIR serialization. `MIR_UNION_NEW`/`MIR_UNION_GET` use the existing `second` field as a nonnegative label index; `-1` remains available for legacy unlabeled MIR with unambiguous record shapes. A structural record can be injected implicitly only when its shape identifies a unique alternative. An immediate constructor call in an expected-union binding or return retains its label; broader source expressions and imported qualified constructors still need work. The C scalar-register compactor must never reinterpret the alternative index as a register.
* Unions with exclusively zero-field record alternatives use an unowned `i64` tag; `MIR_UNION_NEW` writes that tag and `MIR_UNION_TAG` reads it directly. `MIR_UNION_GET` materializes an empty record when actually needed, but match lowering skips the extraction when the pattern binds no fields. After lifetime cleanup, MIR optimization may replace an immediately released empty record followed by enum injection with `MIR_UNION_NEW` whose `first` is `-1` and `second` is the selected alternative; the verifier restricts this source-free form to valid labeled, payload-free enums. No record is allocated by either native execution or MIR interpretation for that form. Unions with any nonempty alternative still use an `S_MirRecord*` tagged wrapper (`fields[0]` tag, `fields[1]` retained record pointer). Arrays and dictionaries keep fixed-size `S_MirField` slots (8 bytes on tested 64-bit targets), not an inline buffer of the largest alternative. A proposed max-payload-width inline layout would require type-dependent strides, active-alternative retain/drop, managed-field handling, and safe extraction of independently owned records after matching. The isolated POD-only C11 comparison in `tools/benchmark_union_storage.py` documents the tradeoff; it is **not** integrated into MIR or C emission and is not an end-to-end Sirius performance result.
* Experimental native coallocation (`SIRIUS_EXPERIMENTAL_UNION_COALLOC`) preserves the pointer-based union ABI and independent record/wrapper ARC identities while sharing one allocation. Post-cleanup MIR instructions `MIR_RECORD_NEW_FUSED` and `MIR_RECORD_NEW_FUSED_MOVE` carry the *union destination register index* in `immediate` (not a type ID); the payload destination and field inputs are otherwise those of their ordinary constructors, including the existing move-input mask for the move form. MIR verification requires immediate `UNION_NEW` and `RELEASE(record)` in the same block. Native emission selects coallocation with a compile-time flag; MIR interpretation ignores the allocation hint. The experimental layout marks **only fixed-size** coallocated records and union wrappers using the high bit of their existing `capacity` word. Growable arrays and ordinary records use unmarked, normal capacities; the native runtime rejects attempts to resize a fused node. No extra record-header word is required. See `ROADMAP.md` for the experiment's measured benefits and limitations.
* Array access becomes a bounds proof/optional result/checked panic path, depending on syntax.
* **Deferred (medium priority):** signed negative array indices normalize relative to array length before the bounds check (`-1` is last element). This applies to reads and CoW writes; optional/checked/proven access retain their current semantics. See `tests/deferred/25_negative_indexing.sirius`.
* Record spread, deletions and overrides are resolved to a new record layout; preserve left-to-right **expression evaluation** even if a field is later overwritten.

## Implemented experimental array MIR

The MIR interpreter and default C backend now support canonical rank-1 `Array[T]` values using `MIR_ARRAY_NEW`, `MIR_ARRAY_GET`, `MIR_ARRAY_LENGTH`, and `MIR_ARRAY_SET`. Element types may be scalars, strings, records or previously interned array types. Index reads and writes are checked (no negative-index normalization yet). `MIR_ARRAY_SET(dst, owner, index, value)` **consumes** the owned `owner` register, invalidating it if distinct from `dst`. The array is updated in place only when uniquely owned; shared arrays are cloned, retaining managed elements and releasing the replaced element. Copies retain the collection handle; recursive release follows canonical element descriptors. A separate CFG ownership/lifetime pass remains planned.

## Memory management in MIR

Value semantics have to be visible in the compiler, not reconstructed from textual C:

* `Retain` and `Release` track managed storage (implemented for MIR strings and records); the MIR C backend uses canonical record descriptors to generate recursive field drops. Arrays/variants still require implementation.
* A plain copy of an inline record copies scalars and retains managed fields. Records may therefore share nested arrays safely.
* `CoWSet(root, path, value)` resolves nested field/index updates and assures unique ownership of any modified buffer. Reuse uniquely owned allocation; otherwise copy the path (with reference management).
* Function inputs are *logically immutable*. For a nonescaping read-only parameter C may safely borrow, but retained/returned/stored values must have well-defined ownership credits.
* Function returns transfer ownership to the caller. All control-flow exits must release live owned temporaries; the ARC pass can insert necessary releases after CFG creation.
* In the first version, insert conservative retains and releases; ownership/escape/FBIP optimization can come later.

## Worked lowering examples

### `08_array_cow`

Sirius:

```sirius
var a = [10, 20, 30]
let original = a
a[!1] = 99
```

Illustrative MIR (notation rather than exact Python serialization):

```text
a        = array_make_i64(10, 20, 30)
original = alias(a)
retain(a)                    ; one ownership credit for original
index    = const_i64(1)
value    = const_i64(99)
cow_set(a, index[PANIC], value)
...                          ; read a and original separately
release(original)
release(a)
```

### `04_recursion`

```sirius
recur factorial(n - 1, acc * n)
```

```text
next_n   = sub_i64(n, 1)
next_acc = mul_i64(acc, n)
n        = next_n
acc      = next_acc
jump factorial_entry
```

### `16_tagged_union`

```sirius
def Success(value: i64)
    pub value

def Failure(code: i64)
    pub code

let Result = Success | Failure
```

`Success(7)` first produces a record `{value: i64}`. When passed to a parameter of type `Result`, HIR inserts `UnionInject(Result, SuccessTag, record)`; in C this is a tagged union with a record payload. A match checks the tag and extracts the corresponding record before binding its fields.


## Rationale for separating lowering from parsing

The earlier GDScript-to-C++ transpiler combined parsing, inference and emission. Sirius now has separate tokenizer, parser, HIR analysis and MIR emission. The previous combined emitter has been removed; ownership and evaluation order are explicit in MIR.


## Current runtime type layouts (static MIR types)

`Types.runtime_storage`, `Types.runtime_ownership` and `Types.runtime_layout`
expose the representation of canonical `TypeId`s independently of their numeric
positions. `RuntimeLayout(storage, ownership, fixed_slots, variable_slots)`
describes the **current** MIR implementation, not a stable FFI or shared-library
ABI. Storage is `i64`, `f64`, `bool`, `S_String *`, `S_MirRecord *`, or void;
invalid IDs have an invalid layout. Scalar values are trivial; strings own an
`S_String` reference and other composite values generally own an `S_MirRecord` reference. Payload-free unions instead have `i64` scalar storage and no ownership credit.

An `S_MirRecord` contains a reference count, local numeric type index, length,
capacity and `S_MirField` union slots. Records use one fixed slot per field in
canonical name order; arrays use `length` variable slots; optionals use zero
or one; dictionary wrappers use one slot holding `S_Dict *`. Unions with
only empty-record alternatives use zero heap slots: their value is the scalar
alternative index. Other unions use two fixed slots (alternative index and a
retained pointer to a separately allocated record payload), so `Array[Union]`
can mix arbitrarily different payload sizes without changing its element slot
size.
The C emitter
selects union members, retains and releases by the canonical descriptor.
`sizeof(S_MirField)`, alignment and header offsets remain target-ABI-dependent.
The interpreter uses its own heap representation but the same static ownership
classification. Type IDs inside `S_MirRecord` are local to the executable,
**not** portable runtime identities. Reflection, native registration, dynamic
`Any`, union/function descriptors, and versioned runtime metadata remain
separate future work.

## Phase B migration status

HIR generic specialization lookup and lifecycle, symbol binding metadata and structural record-field lookup now use canonical `TypeId`s. The MIR C backend selects layout, field variants and managed helpers from canonical descriptor tags; scalar identity checks in parts of HIR/MIR lowering still compare reserved primitive TypeIds. The module declaration HIR pass precedes emission and supplies function headers; pre-emission body traversal now resolves local lexical scopes, supported scalar and record/collection expressions, indexing modes and selected calls; complete typed bodies for every language feature remain future work; a typed CFG MIR subset is implemented.

## First-class function MIR

Canonical `TYPE_TAG_FUNCTION` signatures record parameter types, return type and an effect flag (currently unchecked). `Fn[parameters...,return]` annotations and named or qualified exported function references lower to `MIR_FUNCTION_REF`; `MIR_CALL_INDIRECT` invokes function-typed scalar IDs. Source expression-bodied, noncapturing lambdas lower to private functions, with contextual parameter-type inference. The interpreter, native C emitter, serialized MIR and linked libraries support these values with relocation of referenced function IDs. Imported concrete functions must be exported and have available bodies; source-free `.smirg` packages cannot provide concrete bodies. Function references have no ARC credit. Contextual generic function references reuse the ordinary HIR named-call specialization worklist when an expected `Fn` signature is available, including source-free `.smirg` generic declarations. Generic callback combinators, source-free concrete bodies and transitive purity/effect enforcement are deferred.

**No implicit captures.** `Fn` is a scalar function ID with no ARC
credit. Source lambda bodies have independent lexical scopes, so attempting
to reference an enclosing local is a type-checking error. There is no hidden
environment argument in either backend, and capturing closures are not a
planned feature of Sirius.

The explicit-context model is exercised by `Std.Functional.map_with_context`.
The MIR regression in `tools/test_mir_closure_environment.py` also verifies
that an ordinary owned record `{code: Fn[Env, i64, i64], env: Env}` can cross
function boundaries, retain managed fields, preserve CoW, survive MIR wire
format and linking, and invoke its code with `env` supplied explicitly. This
uses existing record and function-reference instructions; it is not a new
`Fn` representation or lexical capture mechanism.

## Implemented experimental dictionary MIR

Source constructor unions use canonical `(label, structural record type)`
alternatives, ordered by label. Empty `rec` payloads are valid, allowing `enum`
as source sugar. `MIR_UNION_NEW` and `MIR_UNION_GET` reuse the existing `second`
instruction slot for explicit alternative indices, independent of payload
shape; unlabeled legacy MIR uses `-1` for uniquely shaped payload lookup.
The interpreter and C backend use a scalar tag for payload-free unions and a
managed wrapper for unions with payloads. HIR matches source constructor labels
and annotates canonical alternative indices, so equal-shaped alternatives do
not collapse during lowering.

`MIR_DICT_NEW`, `MIR_DICT_INSERT`, `MIR_DICT_GET_OR`, `MIR_DICT_LENGTH`, `MIR_DICT_NEXT`, `MIR_DICT_KEY`, and `MIR_DICT_VALUE` operate on canonical `Dict[K,V]` descriptors. `K` may be `i64`, `bool`, `f64`, `string`, or a canonical record, optional, or union recursively containing hashable payloads (not arrays/dictionaries); `V` can be any MIR-supported type, including managed arrays/records/dictionaries. Native MIR C uses the shared runtime's open-addressed `S_Dict` through an owned `S_MirRecord` wrapper; the interpreter retains list-based storage. `MIR_DICT_INSERT` consumes its owner, reuses unique storage, or clones shared dictionary entries while retaining nested values. Existing keys are replaced without changing entry count. Structural key hashes and equality traverse canonical record fields, optional presence, and union alternative tags/payloads; signed floating zero hashes identically, and all NaNs have one dictionary key equivalence class and hash. Source `==` retains IEEE NaN behavior. `MIR_EQ_VALUE` compares record, optional and union values without consuming ownership; its interpreter/C implementations recursively compare nested arrays, but direct source array `==` is rejected pending elementwise semantics. The verifier checks key/value/result types. `MIR_DICT_GET_OR` accepts an already evaluated fallback register, **not** an `Optional` result, and must not be used as a direct lowering of lazy source `or`. Read-only cursor operations enumerate dictionary entries for nested value coercions without modifying the source. Source `Dict[K,V]()`, `.insert`, and `len(dict)` are supported experimentally; source `.get` now lowers through Optional and CFG control flow.

## Implemented experimental optional MIR

Canonical `Optional[T]` values use zero/one owned payload fields, including nested managed values. `MIR_OPTIONAL_NONE`, `MIR_OPTIONAL_SOME`, `MIR_OPTIONAL_HAS`, `MIR_OPTIONAL_UNWRAP`, `MIR_ARRAY_GET_OPTIONAL` and `MIR_DICT_GET_OPTIONAL` are verified and executed by both the Sirius MIR interpreter and the MIR-C backend. The interpreter maintains reference counts; C uses the existing managed-record runtime with descriptor-directed nested release.

HIR-to-MIR lowering now handles `a[?i]`, `dict.get(key)`, postfix `!`, `optional or fallback` and `let x = optional else return value`. The latter two produce actual CFG branches, so fallback expressions execute only for absent values. The older `MIR_DICT_GET_OR` remains explicitly eager and must not be used to lower source-level `or`. The implemented CFG ownership/lifetime passes follow this lowering, as described below. See `tools/test_mir_optional.py` and `tools/test_mir_run.py`.

## Explicit runtime failure edges (experimental)

`src/mir_guard.sirius` splits checked `MIR_DIV_I64`, `MIR_REM_I64`, `MIR_SHL_I64`, `MIR_SHR_I64`, `MIR_ARRAY_GET`, `MIR_ARRAY_SET`, and `MIR_OPTIONAL_UNWRAP` into validation and continuation/panic blocks. Pure `MIR_NONZERO_I64`, `MIR_DIV_NO_OVERFLOW_I64`, `MIR_SHIFT_VALID`, `MIR_ARRAY_INDEX_VALID`, and existing `MIR_OPTIONAL_HAS` predicates preserve the original panic messages, including the `INT64_MIN / -1` overflow case. This pass runs **before** lifetime and exit cleanup; the latter release owned registers on the newly explicit failure edges. Guarded instructions are marked to make repeated lowering idempotent. Both backends retain defensive checks for unguarded manually constructed MIR. This is not general exception unwinding: allocator failure and other implicit aborts remain outside the CFG model.

## Experimental CFG lifetime insertion

`src/mir_lifetime.sirius` analyzes each MIR function using backward register liveness to a fixed point across CFG backedges. At a last use or dead definition of a managed register, it inserts `MIR_RELEASE`. Explicit consuming operations (`MIR_MOVE`, `MIR_ARRAY_SET`, `MIR_DICT_INSERT`) do not release consumed sources; copies and calls retain their existing ownership semantics. The pass is run after typed MIR construction and before final verification, and is idempotent. Forward definite-initialization (`src/mir_ownership.sirius`) runs before and after lifetime insertion. It intersects initialized registers at CFG joins and loop backedges, with explicit move/release invalidation, to reject invalid uses statically. Both passes share operand-read definitions.

A second pass (`src/mir_cleanup.sirius`) performs **path-sensitive ownership cleanup**. Using one snapshot of forward may-ownership and backward liveness, it inserts conditional releases for managed registers dead on each CFG edge, splitting conditional edges as needed. This avoids repeated whole-CFG analysis after every edge rewrite; the rewritten graph is reanalyzed once for *may*-ownership exit cleanup and verified for balance. An additional *may-initialized* forward union analysis identifies values owned on **any** path to a return or explicit panic. Exit cleanup uses `MIR_RELEASE_IF_INIT` for possibly owned registers, preserving the returned value. No post-edge *must*-ownership pass is required for this conditional release strategy. `mir_check_balance` rejects reachable exits that may retain any other managed register. The conditional release uses nullable managed pointers in verified C (defensive direct C emission retains initialization state) or register validity in the interpreter; its effect is tracked by both analyses. Cleanup is idempotent. Tests cover branches, joins, nested managed arrays, explicit conditional releases, native/interpreter agreement, and prior lifetime behavior. Covered division, checked indexing/update and unwrap failures now have explicit cleanup exits; allocator failures and other implicit aborts remain non-unwinding. An optional `mir_audit_return_credits` interpreter check traverses the heap reachable from the returned value and compares expected incoming reference credits with recorded counts, also rejecting leaked unreachable objects, corrupted counts, wrong-type or out-of-range handles. It counts each field of a shared parent once, but every repeated child reference separately; `tools/test_mir_credits.py` checks nested collections, CoW field updates, loops, branches and caller/callee paths against native emission. This checks **one completed execution**, not all CFG paths. Final `mir_check_balance` additionally audits managed source/destination credit transitions on both must-own and may-own CFG states: borrowed operands preserve their owner, transferred/released operands lose it, and a managed result has one owned credit even when replacing an existing value. These are static **register-level** obligations, not a complete proof of nested heap credits, feasible path correlations or exceptional unwinding. `tools/test_mir_credits.py` covers conditional replacement at a CFG join and moves into occupied destinations in addition to returned graphs. Heap-wide static ownership-credit proofs remain future work; process-fatal failures do not require caller-frame unwinding.

Final balance verification propagates must-initialization (intersection) and may-ownership (union) together in one forward worklist seeded at the CFG entry. Each reached successor is processed at least once, even if the predecessor's state is initially unchanged. This avoids unnecessary initial processing of all reachable blocks, reuses reachability and predecessors, and checks register validity before exit balance. Standalone callers can still request one analysis only. Final balance verification reuses the same CFG reachability, predecessor lists and definite-initialization states to check both register validity and managed-reference balance. Scalar-only functions skip the may-ownership solver. Public standalone checks keep the same diagnostics.

MIR lowering keeps source syntax, typed HIR annotations, canonical types, and call
resolution in a read-only `MirLowerContext`; `MirBuilder` carries only mutable
registers, CFG blocks, scopes, and loop targets. The forward ownership worklist
precomputes sparse register write effects for each basic block and applies one
state transfer per block, preserving sequential move/redefinition behavior.
Must/may joins update an owned dense mask rather than allocating a new one per
predecessor. Instruction-level validation still uses ordered reads/writes.

The verified C emitter centralizes managed-value destination replacement in
`static inline` string/record store helpers. The new owned value is evaluated
before replacing and releasing the old one, preserving aliasing, CoW, and
self-assignment semantics; directly supplied, unverified MIR still uses its
explicit checked stores. This reduces repeated C source without altering the
MIR ownership graph. For ownership-verified C emission, scalar register storage
is also allocated using CFG liveness and a packed interference graph. Only
non-argument `i64`, `bool`, and `f64` registers can share a physical slot;
managed values use forward CFG may-ownership and an interference graph to
share slots across disjoint ownership intervals, including cross-block ones.
Instruction reads/writes and conditional cleanup also cause interference to
prevent false releases or clobbering. Joins conservatively union may-owners;
original MIR, interpreter, and defensive emission remain unchanged.

The combined compiler path uses unchecked *internal* guard, lifetime and cleanup transformations, followed by `src/mir_opt.sirius` peephole optimization, between an initial ownership verification and final ownership-balance verification. An adjacent managed `MIR_COPY`/`MIR_RETAIN` and source `MIR_RELEASE` become `MIR_MOVE` when destination and source differ. Conditional/path-dependent releases are not fused. Ownership and liveness state helpers skip writes that leave a CoW state array unchanged. The final failure audit reuses that verification. Individual public MIR passes still validate their inputs and outputs; intermediate checks are not omitted from standalone tests.

### MIR fallibility audit (implemented)

`mir_failure_info(op)` is the shared instruction-level contract. `guarded` marks synchronous operations that must be lowered to explicit `Panic` edges; `abort` marks operations that may terminate outside the current function's CFG (notably allocation and callee failures). `MIR_ARRAY_SET` has both properties: bounds failure is guarded, allocation failure during CoW is not unwound.

`mir_audit_failures()` runs after guard insertion and after full source-to-MIR cleanup. Its independent `in_band` counter identifies operations that encode ordinary absence/failure as values (including `Optional`, bool status, or IEEE-754 nonfinite results); this is *not* an exceptional cleanup path. Executable `Result` unions return and own their active alternative normally, while exhaustive matching belongs to HIR. It rejects unchecked guarded instructions and misplaced guard markers, while counting non-unwinding operations. For guarded opcodes it verifies that **every incoming CFG path** has a matching predicate with a panic failure edge, allowing intervening cleanup-only blocks and the two required integer-division checks. This is a proof for the guard-lowering shape, not a general-purpose dominance solver; fatal failures terminate the process and therefore do not require calling-frame unwinding. The verified C entry point runs this audit before omitting defensive checks. Handwritten MIR can use defensive backend traps without passing the compiler-produced-MIR audit. Numeric overflow semantics (apart from division) remain undecided.

## MIR migration: string methods and record updates

The experimental MIR defines typed string operations for `byte_at`, `slice`,
`find`, `starts_with`, `ends_with`, `join`, and comparisons. `byte_at`/`find`
return `Optional[i64]`. Shared operand-read and type-verification rules apply
to the interpreter and C backend. Compiler guard metadata does not reinterpret
arbitrary string-literal contents.

Direct record-field assignments use `MIR_RECORD_SET(dst, owner, field, value)`,
which consumes the owned record and modifies it in place when uniquely owned.
If another value retains the record, C and interpreter clone the record and
retain its managed fields before replacing the selected field. The incoming
value is retained before releasing the old field, including self-assignment.
For `r.items = r.items.append(x)`, `MIR_RECORD_ARRAY_APPEND` fuses the
record and array updates instead: consume the record, make the record unique
if shared, then append to its array field without extracting a temporary
retained array. If the array itself has other owners it is still cloned.
Nested record/checked-array assignment paths read each projection and index once,
then update the leaf and rebuild ancestors using existing consuming `MIR_RECORD_SET`
and `MIR_ARRAY_SET` operations. Checked-index compound assignments reuse the same path reconstruction and CoW operations.

The committed C bootstrap compiles the native `modular_cli` source root;
`COMPILER_SOURCES` and its alias remain only for legacy test driver assembly.
The native MIR fixed point is verified with `tools/test_bootstrap.py` and
`tools/test_mir_selfhost.py`. The default MIR backend passes 96 positive fixtures and 50 expected
diagnostics. Historical legacy-negative programs accepted by MIR are positive
fixtures.

## Storage review (post-MIR-default)

- **HIR:** `HirNode` is a small typed annotation over source AST IDs, not a
  second syntax tree. `HirAnnotationIndex` uses a per-source dictionary head and
  an array of predecessor links for repeated annotations; lowering builds this
  index once per function. Keep it until a measured lookup bottleneck warrants
  changing the representation.
- **MIR:** `MirInstruction` stores general-purpose operands plus `inputs` and
  `text`; even many scalar operations construct empty input arrays. Blocks own
  instruction arrays and functions own block/register-type arrays. Packing
  operands or using opcode-specific layouts may save memory, but would change
  the verifier, optimizer, interpreter, and C emitter simultaneously; defer it.
- **Ownership:** CFG analyses maintain dense register-state arrays and cache
  per-block instruction effects. Liveness worklists share one empty state per
  function; CoW isolates it when an instruction makes a value live. Measured
  native compilation is faster despite slightly larger cumulative allocation
  requests. The prior standalone intersect/union helpers
  were unused; the active worklist exclusively uses `mir_ownership_join`.
  A subsequent CoW callsite profile finds large cumulative copies from CFG
  joins/transfers and parser arena appends; keep the array/record value
  semantics rather than disabling cloning. See `MIR_PROFILE.md`.
- **Runtime boundary:** generated MIR-C records and collections have typed
  layouts distinct from the generic `S_Array`/`S_Dict` C runtime and the
  specialized legacy `i64` collections. Consolidation requires an ABI and
  ownership plan, not simply moving functions into the same source file.

For now prioritize preserving the native bootstrap fixed point and differential
behavior over compact MIR storage or speculative container unification.

### CFG facts and MIR pass boundaries

`mir_cfg_facts(function)` computes the reachability mask and predecessor lists
for a fixed CFG. Forward ownership and backward liveness may share this snapshot;
`mir_cleanup_function` does so before inserting edge cleanup, then recomputes
facts for the modified graph before analyzing exits. A snapshot must never be
reused after a pass adds blocks or changes terminators.

The combined compiler pipeline checks initial MIR ownership, then applies guard
insertion, lifetime insertion, edge/exit cleanup, and the ownership peephole
optimizer without redundant intermediate verification. Its final balance and
failure audit validate the result. Public individual pass entry points retain
their own checks for independently constructed MIR.

### Local record destructuring (MIR backend)

`let {binding = .field, ...} = expression` lowers to one evaluation of the
record expression followed by typed `MIR_RECORD_GET` operations. HIR checks
field existence and duplicate bindings and preserves ordinary lexical scope;
MIR lifetime cleanup manages the temporary owner and field values. This does
not introduce recursive patterns or mutable destructuring, and the retained
old emitter had rejected the syntax.
